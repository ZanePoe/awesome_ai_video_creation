# 2026-11-25 合集多语言化

需求：所有 awesome 合集改为多语言版本——默认英语、保留中文，并至少覆盖世界使用人数前五的语言。

## 语言集合

`en`（默认，仓库根）、`zh`、`es`、`hi`、`fr`。选择依据是 Ethnologue 口径的总使用人数前五（英语、中文普通话、印地语、西班牙语、法语）；本组语言均为从左到右书写，不需要 RTL 处理。

## 布局

- 根目录 = 英文版：`README.md`、`docs/projects.md`、`docs/rankings.md`、`docs/{taxonomy,methodology,research,cli-comparison}.md`、`CONTRIBUTING.md`
- `locales/<lang>/` = 其余语言的完整镜像：`README.md`、`docs/*`、`CONTRIBUTING.md`、`ui.json`，`en/es/hi/fr` 另有 `entries.json`
- 每个语言版本的 README 第一行是语言切换行；镜像内 `docs/`、`CONTRIBUTING.md` 相对路径写法与根目录相同，只有指向仓库根的共享文件（`LICENSE`、`data/`、`scripts/`、`record/`）需要 `{R}` 前缀（英文为空，镜像为 `../../`）
- `record/` 保持撰写时的中文原文，作为核验审计痕迹，各语言 README 末尾统一注明这一点

## 数据来源分层

- `data/projects.json` 仍是中文规范数据，功能、边界与许可审核结论只在这里维护一次；`zh` 渲染直接回落该文件，不生成 `locales/zh/entries.json`
- `locales/<lang>/ui.json`：分类、层级、许可状态、维护层、排序视图名、表头、章节标题与段落模板；键集合、模板占位符与中文版严格一致，`validate()` 逐 locale 断言，且禁止残留汉字
- `locales/<lang>/entries.json`：`repo → {description, boundary, license_label, license_note}`，覆盖全部仓库且四字段非空，缺任一条即报错
- `data/rankings.csv` 去语言化：列 `maintenance_status`（中文串）改为 `maintenance_tier`（0-3），语言标签只在渲染时从 ui.json 取

## 脚本与门禁

- `scripts/build.py` 重写为 locale 层：`LOCALES`、`ui(locale)`、`entries(locale,projects)`、`placeholders(template)`、`path(locale,name)`、`prefix(locale)`、`anchor(title)`、`switcher(langs,locale)`、`check_links()`、`KEYWORD_FILES`、`INLINE`、`GENERATED`，`render(locale,…)` 每语言输出三份文件，`validate()` 增加 locale 完整性检查（键集合、占位符、条目覆盖、显示名、无残留汉字）
- `scripts/I18N.md` 记录布局、占位符规则与译文纪律（事实不得增删；仓库名、URL、commit、许可证标识、模型名、代码块、表格结构原样保留；`docs/research.md` 的字面检索关键词不译）
- `tests/test_i18n.py`：五语输出齐全、切换行链接在磁盘上可达、README 内部锚点有效、相对链接存在、非中文 locale 无残留汉字、`zh` 正文仍来自规范数据、CSV 语言中立、删除任一条 locale 条目必须让 `validate()` 失败
- `.github/workflows/refresh.yml`：每日刷新提交范围扩到 `README.md docs locales`

## 三处需要定规则的冲突

1. 检索关键词 vs「非中文 locale 不留汉字」：`docs/research.md` 的中英关键词表与内容工厂 curl 查询串是「可复现检索」的数据本身，音译会破坏审计价值。决定：保留原文，并把它作为唯一豁免文件写进代码——`build.KEYWORD_FILES=['docs/research.md']`，`tests/test_i18n.py` 对非 `zh` locale 只允许汉字出现在表格行（行首 `|`）或反引号内，正文行出现汉字即失败；其它 5 个静态文档仍要求全文无汉字。
2. 相对链接在镜像里层级算错会指到别处：静态文档的链接按「文件自身目录」解析，`locales/<lang>/docs/research.md` 要到仓库根需要上三层（docs→`<lang>`→locales→根），即 `../../../research/xxx.json`；英文版 `docs/research.md` 只需 `../research/xxx.json`。`locales/<lang>/CONTRIBUTING.md` 是两层，根 `CONTRIBUTING.md` 无需上跳。`docs/readme-intro.md` 因为会被嵌进 README，改按语言根目录解析（`build.INLINE`），两种布局写法相同。决定：`build.check_links()` 按上述基准逐 locale 校验并由 `validate()` 调用；生成物链接用 `{R}`（英文 `""`、镜像 `../../`）；`locales/zh/docs/research.md` 的 7 条链接已改为三层。
3. 项目显示名含汉字：`data/projects.json` 有 3 条 `name` 带汉字（`漫剧老李 Skill`、`魔因漫创 Moyin Creator`、`火宝短剧 Huobao Drama`），照直渲染会让 en/es/hi/fr 的 README 与详表出现汉字，与规则 1 冲突，而这些名字是审核数据里的规范标识。决定：`entries.json` 增加可选 `name`（只这些条目需要），`build.entries()` 取 `t.get('name') or p['name']`，`render()` 的速览表、分类目录前三、详表标题与排序表全部改用 locale 显示名；`validate()` 要求规范名带汉字的项目在每个非中文 locale 必须提供无汉字 `name`，否则报 `missing localized display name`。后两条沿用项目名里已有的官方英文部分（`Huobao Drama`、`Moyin Creator`），第一条无官方拉丁名，按逐词拼音写作 `Manju Laoli Skill`。`data/rankings.csv` 仍写规范 `p['name']`；语言切换行里的 `简体中文` 是语言自称（endonym），不计入违规。

## 等价性验证

重构后仅渲染 `zh` 与当时的根目录文件逐行比对：`docs/projects.md`（1094 行）与 `docs/rankings.md`（459 行）除新增语言切换行外零差异；`README.md` 差异仅三处——切换行、`../../LICENSE` 前缀、新增的变更记录尾注。中文分类目录表原本用「、」连接，重构第一版误用「 · 」，因此把分隔符提为 `ui.json` 的 `list_separator`，`zh` 保持「、」，其余语言用 `, `。

## 落地过程中被推翻的三处实现错误

1. `prefix()` 深度算错：第一版按 `('../'*(1+depth))` 实现，镜像 README 的 `{R}LICENSE` 渲染成 `../LICENSE`（指向 `locales/LICENSE`，404）。正确口径是镜像根距仓库根两层：`('../'*(2+depth)) if locale!=DEFAULT else ('../'*depth)`。由并行代理比对盘面发现，已修正并重新生成五语产物（`locales/zh/README.md` 现为 `../../LICENSE`）。
2. `validate()` 里递归收集模板键的辅助函数写成 `sorted(k for child in [...])`，`k` 未定义，直接 `NameError`；任何 locale 的检查都跑不到。改为 `sorted(sum([...],[]))`。
3. `test_csv_is_language_neutral` 最初断言 `header[-2]=='maintenance_tier'`，而 14 列里倒数第二列是 `score`，断言恒假。改为按列名取索引（`header.index('maintenance_tier')`），不写死下标。

另外两处收紧：
- 「不留汉字」判定从 Han 区间扩为完整 CJK 范围常量 `build.CJK`（含 `、`、`「」`、全角括号与假名区），供 `validate()` 与测试共用一份正则；`docs/research.md` 的关键词表格行与反引号内容仍按 `KEYWORD_FILES` 逐行豁免。
- `check_links()` 的生成物豁免从「href 字面等于 `docs/projects.md`」改为「解析后的绝对路径 ∈ 该 locale 的生成物集合」，这样平级写法（`docs/research.md` 里写 `projects.md`）也不会误判。

同时修掉一处事实陈旧：`docs/research.md` 原句「没有安装和运行 72 个项目」已与收录数不符，五语统一改为不写死数量（zh「没有安装和运行合集中的项目」）。

## README 开头的分类标签导航

每份 README 在 intro 之后、「当前收录」之前新增 `## 分类导航`（en `Jump to a category`、es `Ir a una categoría`、hi `श्रेणी पर जाएँ`、fr `Aller à une catégorie`），一行内列出该语言全部分类的页内链接，顺序与 `ui.json.categories` 一致，可点击跳到对应 `### 分类` 小节。

同时修正 `anchor()`：与 GitHub 实测对照（抓取 `github.com` 渲染页面里每个 `### 分类` 自带的锚点链接逐一比对）——GitHub 的 README 标题 id 会**删除** `、`、`.`、`,` 等标点、**保留**天城文组合符（matra）与中日韩文字、空格转 `-`。原先用 `str.isalnum()` 的实现恰好符合这一条（组合符不是 alnum，需要额外放行 Mn/Mc/Me），中途曾按 `github-slugger` 的 npm 包规则改成保留 `、`，实测 6 个含 `、` 的中文分类锚点全部跳不动，已回退为「保留字母/数字/组合符/`_`/`-`，其余标点删除」。`tests/test_i18n.py` 新增 `test_tag_navigation_covers_every_category` 断言导航链接与 `### ` 小节一一对应。

## 局限

- 译文由模型生成，未经母语者复核；术语取舍记录在各语言的 `CONTRIBUTING.md` 与 `docs/research.md` 语境中，发现误译应直接改 `locales/<lang>/` 下的对应文件
- `record/`、`research/` 目录与 GitHub Actions 日志保持中文/英文原文，不做机器翻译，以免破坏审计痕迹
- 每日指标刷新只覆盖生成物；新增项目仍需按 `CONTRIBUTING.md` 同时补齐四个非中文 locale 的 `entries.json`，否则 CI 失败
